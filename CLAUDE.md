# Working on KNM (nederlands.app; repo: knm)

A course for the KNM exam (Kennis van de Nederlandse Maatschappij) of the Dutch civic integration, built on the infrastructure of The Mantiqi (repo Nawidhbr/themantiqi). Owned by AQLI; all rights reserved (`LICENSE`). Background: `docs/ARCHITECTURE.md` (how it fits together), `docs/CONTENT.md` (how to write and check a lesson), `docs/DEPLOY.md` (Vercel, environment variables, launch checklist).

## Rules

- Run `npm run check` before committing: unit tests, content validation, build, `scripts/check-site.mjs` and the Playwright tests in `e2e/` (learning, unlocking, layout on desktop and phone, accessibility with axe in light and dark). GitHub Actions runs the same on every push. A change to a study rule or to selling gets a test.
- Never hard-code the domain: `SITE_URL` in `apps/web/src/config/site.ts`. The site name is `SITE.name` ("KNM"). Indexing only through `INDEXING=on`; no `Disallow` rules.
- Vercel builds from the repository root (`npm run build` → `dist`), so that `vercel.json` and `api/` are deployed; `.github/workflows/uptime.yml` raises an issue when they are not.
- Dutch is the source language. Every text field is `{ nl, en? }`; interface text lives in `apps/web/src/i18n/<code>.json` (nl the base), read with `t()` and `fmt()`. Never write interface text into a page. Every URL starts with the locale.
- Content lives in `packages/content`, validated against `src/schema.ts`; the site imports only `generated/*.json`.
- The eindtermen (`packages/content/eindtermen.json`, Staatscourant 2024, 15802) are the spine: every lesson names its crucial actions (`handeling`), every question the knowledge item it tests (`eindterm`); unknown codes fail validation. `npm run coverage` shows what is tested and checked.
- Every new lesson has `checked` (the day it was checked against its sources) and every question a `source` (the index of the lesson source behind the right answer). Sources are official pages. Questions may be drafted with AI but go in only after that check.
- Never use real exam questions or copy DUO's practice exams; never call the site official; keep "niet verbonden aan DUO of de overheid" visible. Facts that change (names in office, amounts) stay out of lessons.
- Everything is a draft until a qualified teacher has reviewed it; enter a review in `reviews.json` only when it was given. Keep the draft badge visible (`components/ReviewBadge.astro`).
- Study rules live only in `apps/web/src/lib/progress.js` (tested in `apps/web/test/`): themes open from the start; inside a theme lessons open one by one at two stars; stars 1 from 4, 2 from 7, 3 from 9 out of 10; smart review (`reviewAfter`: a wrong answer comes back at once, then after 1, 3, 7 days, retired after four right); merging progress from a link (`mergeProgress`: best score wins). Scores, review and bought access stay in the browser (`scores`, `review`, `access`); every answer is passed to `window.__review` (scripts/head-study.js).
- Reading aloud: `scripts/read-aloud.js` (browser speech, buttons only when there is a voice for the language) on lessons, review and the exam. Drawings: `lib/pictures.ts`, one per lesson (`picture` in the content).
- Practice: `/practice/` (chosen passed lessons, and smart review), `/exam/` (practice exam, `config/exam.ts`: 40 questions spread over the themes, 45 minutes, results per theme; needs access while selling), `/transfer/` (progress to another device in a `#p=` link, noindex).
- Selling (Mollie, off until `PAYMENTS=on` and the details in `config/company.js` are complete): `config/offer.js` (€7.99 incl. 21% VAT, 365 days, theme 1 free). No accounts, no database: the access code is the Mollie payment id signed with `ACCESS_SECRET` (`api/_access.js`); see `docs/ARCHITECTURE.md`. Keep the terms page, the confirmation mail and the privacy page in step with the offer.
- Strict CSP in `vercel.json`: no inline scripts and no `on…=` attributes. A page script is a file in `apps/web/src/scripts/`, imported with `?url` and loaded with `<script is:inline src={url}>`; data goes in `data-vars`. A new outside resource needs a CSP entry.
- SEO (`components/Seo.astro`): one `<h1>` per page (notes that stand in for a heading use `role="heading"`); titles within 65 characters, descriptions about 155, written for what people search ("KNM oefenen", "KNM-examen", "oefenvragen"); main pages take their own title from `seo` in the dictionaries, themes and lessons from `study.themeSeoTitle`/`lessonSeoTitle`, others end in `meta.titleSuffix`. Structured data in `lib/structured-data.ts`.
- House style "Stedelijk" (`styles/palettes.css`, `SITE.palette` "mondriaan"): white, thin black rules (light in dark mode), square corners and tiles, Inter Tight 800 headings, small blocks of flag red (#AE1C28), flag blue (#21468B) and orange (#FF7A00). Orange (`--red-fill`) marks the current item and the main action and always carries black text. Colours are tokens; never hard-code one in a page. Buttons are not in capitals. Lessons in Atkinson Hyperlegible, the knowledge base in Literata.
- PWA: add new page types to `lib/routes.ts` so they work offline.
- Not ported from The Mantiqi (port when needed): accounts (Supabase), previews of locked lessons, the editing screen (Keystatic), the news finder.
